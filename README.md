# 🎙️ SoundOS — مساعد نظام Ubuntu الصوتي الذكي

**SoundOS** هو مساعد ذكي لنظام **Ubuntu Linux** يتيح للمستخدم التحكم في النظام، إدارة الملفات، وتنفيذ الأوامر بالصوت (باللهجة المصرية أو الإنجليزية) باستخدام **Google Gemini API**، مع التركيز على الأمان التام والخصوصية ومنع الأخطاء الكارثية.

---

## 🏗️ معمارية المشروع (Modular Architecture)

تم إعادة هيكلة المشروع من ملف واحد إلى **8 وحدات مستقلة (Modules)** لتسهيل العمل الجماعي وتوزيع المهام بين الفريق دون تعارض في الكود:

| الملف | الوظيفة والمسؤولية |
| :--- | :--- |
| **`main.py`** | نقطة الانطلاق الرئيسية لتشغيل التطبيق. |
| **`config.py`** | ملف الإعدادات المركزية (المسارات المسموحة، الموديلات المفضلة، قواعد الأمان، ووضع المطورين). |
| **`audio_recorder.py`** | تسجيل الصوت من المايكروفون وتحويله لـ `WAV` في الذاكرة (`RAM`) مباشرة دون ترك ملفات مؤقتة. |
| **`ai_engine.py`** | التواصل مع **Gemini API**، اكتشاف الموديلات تلقائياً مع نظام بدائل (Fallback)، وتحليل أوامر المستخدم. |
| **`context_scanner.py`** | فحص أسماء ومسارات الملفات في النطاق المسموح فقط (`Metadata Only`) دون قراءة محتواها لحماية الخصوصية. |
| **`executor.py`** | فلترة الأوامر، استبدال الحذف العادي بسلة المهملات (`gio trash`)، وتنفيذ الأوامر بأمان. |
| **`gui.py`** | واجهة المستخدم الرسومية (حالياً `Tkinter` وجاري نقلها إلى `Flask`). |
| **`requirements.txt`** | قائمة المكتبات البرمجية المطلوبة لتشغيل المشروع. |

## 🔄 مسار البيانات ورحلة الأمر الصوتي (Audio & Data Workflow)

يمر الصوت منذ لحظة تسجيله وحتى تنفيذ الأمر على النظام بـ **5 مراحل متتالية** تضمن السرعة، الخصوصية، والأمان:

1. **الالتقاط في الذاكرة (`audio_recorder.py`):** يُسجَّل الصوت من المايكروفون (`16kHz, Mono`) ويُحوَّل إلى بايتات `WAV` داخل الـ **RAM** مباشرةً دون كتابة أي ملفات مؤقتة على القرص الصلب.
2. **فحص سياق البيئة (`context_scanner.py`):** بالتوازي، يجمع النظام أسماء ومسارات الملفات والمجلدات في النطاق المسموح فقط (`Metadata Only`) دون فتح أي ملف لحماية الخصوصية.
3. **التحليل الذكي (`ai_engine.py`):** تُرسَل بايتات الصوت وخريطة الأسماء إلى **Google Gemini API** (مع نظام التبديل التلقائي بين الموديلات) لاستخراج 4 حقول: `STATUS`، `TRANSCRIPT`، `INTENT`، و `COMMAND`.
4. **التحقق من التعارض والعرض (`gui.py`):** إذا كان الاسم موجوداً مسبقاً (`STATUS: CONFLICT`) يطلب النظام اسماً بديلاً، أما إذا كان جاهزاً (`READY`) فيُعرض الوصف البشري (`INTENT`) للمستخدم قبل التنفيذ.
5. **التأمين والتنفيذ (`executor.py`):** يُفحص الأمر ضد الأوامر الخطيرة (`rm -rf`, `mkfs`, `dd`)، ويُحوَّل الحذف العادي (`rm`) تلقائياً إلى سلة المهملات (`gio trash`) قبل التنفيذ في بيئة Ubuntu.

```mermaid

    User(["🎙️ User Speaks (Arabic / English)"]) --> Rec["audio_recorder.py<br/>Record WAV in RAM (No Disk Files)"]
    User --> Scan["context_scanner.py<br/>Scan File Names Only (Metadata)"]
    
    Rec -->|Audio Bytes| AI["ai_engine.py<br/>Google Gemini API + Auto-Fallback"]
    Scan -->|File Context| AI
    
    AI --> Decision{"Check Status"}
    
    Decision -->|STATUS: CONFLICT| Conflict["⚠️ Name Already Exists!<br/>Ask user for a new name"]
    Decision -->|STATUS: READY| Ready["✅ Show Human Intent (INTENT)<br/>Hide Bash unless DEV_MODE=True"]
    
    Ready -->|Click Execute| Exec["executor.py<br/>1. Check Dangerous Patterns<br/>2. Convert rm ➔ gio trash"]
    Exec --> OS(["🐧 Execute in Ubuntu Shell"])

## 🚀 طريقة التثبيت والتشغيل (Setup & Run)

1. **استنساخ المستودع (Clone):**

    git clone https://github.com/awork5814-hue/SoundOS.git
    cd SoundOS

2. **تثبيت متطلبات النظام على Ubuntu (لأول مرة فقط):**

    sudo apt update && sudo apt install -y python3-venv python3-tk libportaudio2

3. **إنشاء وتفعيل البيئة الافتراضية (Virtual Environment):**

    python3 -m venv venv
    source venv/bin/activate

4. **تثبيت مكتبات بايثون المطلوبة:**

    pip install -r requirements.txt

5. **تشغيل البرنامج:**

    python3 main.py

## 📋 قائمة المهام المطلوبة من الفريق (Team TODOs)

تم وضع علامات `TODO` واضحة داخل كل ملف لتحديد المطلوب بدقة لكل عضو في الفريق:

### 1️⃣ تطوير محرك الذكاء الاصطناعي (`ai_engine.py`)
- [ ] **دمج سياق الملفات:** تمرير متغير `file_context` القادم من `context_scanner.py` داخل الـ `System Prompt` ليفهم الموديل مسارات الملفات الحقيقية الموجودة على الجهاز.
- [ ] **تطوير صيغة المخرجات:** إلزام الموديل بإرجاع 4 حقول محددة:
  - `STATUS`: لتحديد ما إذا كان الأمر جاهزاً (`READY`) أم يوجد تعارض في الأسماء (`CONFLICT`).
  - `TRANSCRIPT`: النص المفرغ لما قاله المستخدم.
  - `INTENT`: شرح بشري مبسط للعملية باللغة العربية أو الإنجليزية ليظهر للمستخدم بدلاً من كود الـ Bash.
  - `COMMAND`: أمر الـ Linux Bash التنفيذي.
- [ ] **منع الكتابة فوق الملفات الموجودة (No Auto-Overwrite):** إذا طلب المستخدم إنشاء ملف موجود مسبقاً في `file_context`، يتم إرجاع `STATUS: CONFLICT` وإبلاغه بوضوح أن الاسم مستخدم بالفعل (على غرار نظام Windows) والطلب منه تحديد اسم جديد.
- [ ] **التمييز بين الحذف العادي والنهائي:** التفرقة في الـ Prompt بين نقل الملفات لسلة المهملات (`gio trash`) وبين الحذف النهائي (`rm -rf`) بناءً على صراحة طلب المستخدم.

### 2️⃣ تطوير ماسح البيئة (`context_scanner.py`)
- [ ] استيراد واستخدام `config.ALLOWED_DIRS` و `config.MAX_SCAN_DEPTH`.
- [ ] بناء دالة تمر على المجلدات المسموحة وتجمع **أسماء ومسارات الملفات والمجلدات فقط** دون فتح أي ملف أو قراءة محتواه، وإرجاعها كنص منسق لـ `ai_engine.py`.

### 3️⃣ تطوير منفّذ الأوامر والأمان (`executor.py`)
- [ ] **الحذف الآمن الافتراضي (`sanitize_command`):** فحص أي أمر حذف عادي (`rm `) واستبداله تلقائياً بـ `config.SAFE_DELETE_COMMAND` (`gio trash`) لنقل الملف إلى سلة المهملات بأمان.
- [ ] **كشف الأوامر الخطيرة (`is_dangerous_command`):** مطابقة الأمر مع `config.DANGEROUS_PATTERNS` (مثل `rm -rf`, `mkfs`, `dd`) وإرجاع `True` لتفعيل التأكيد المزدوج في الواجهة.

### 4️⃣ تطوير الواجهة وتجربة المستخدم (`gui.py`)
- [ ] **الترقية إلى واجهة ويب محلية (`Flask`):** نقل الواجهة بالكامل من `Tkinter` إلى **Flask (HTML/CSS/JS)** لدعم اللغة العربية واتجاه النص (`RTL`) بشكل طبيعي وتصميم عصري.
- [ ] **حفظ مفتاح الـ API محلياً:** تخزين الـ `Gemini API Key` في ملف محلي (مثل `api_key.json` أو `.env` — كلاهما متجاهل في `.gitignore`) عند إدخاله لأول مرة، للدخول مباشرة إلى لوحة التحكم في المرات القادمة.
- [ ] **إخفاء الأكواد عن المستخدم العادي:** عرض وصف العملية (`INTENT`) فقط للمستخدم، وإخفاء أمر الـ `Bash` إلا في حالة تفعيل `config.DEV_MODE = True`.
- [ ] **التعامل مع التعارض والخطورة:**
  - إظهار رسالة تنبيه تطلب اسماً جديداً عند استلام `status == "CONFLICT"`.
  - إظهار نافذة تأكيد مزدوجة قبل تنفيذ أي أمر خطير يرجع `True` من `executor.is_dangerous_command()`.

## 🔮 التحسينات المستقبلية (Future Roadmap)

- [ ] **المحادثة التفاعلية المستمرة (Multi-Turn Context):** الاحتفاظ بسجل آخر بضعة أوامر ليتمكن المستخدم من قول *"طب سميه ملف_جديد"* أو *"انقله للديسكتوب"* دون إعادة الجملة من البداية.
- [ ] **التنفيذ التلقائي للأوامر الآمنة (Auto-Execute Mode):** خيار في الإعدادات لتنفيذ أوامر القراءة والاستعلام الآمنة (مثل فتح برنامج أو عرض المساحة) فوراً دون الحاجة للضغط على زر `Execute`.
- [ ] **دعم الاختصارات الصوتية والتنشيط بالكلمة (Wake Word):** إمكانية تشغيل التسجيل باختصار كيبورد عالمي (Global Hotkey) أو كلمة تنبيه صوتية.
- [ ] **سجل العمليات والتراجع (Action History & Undo):** تسجيل العمليات المنفذة في الجلسة مع إمكانية التراجع السريع عن عمليات النقل أو إعادة التسمية.
